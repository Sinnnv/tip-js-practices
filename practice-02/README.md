## Модель данных и структура модулей

Модель задачи:
```js
{ id: number, title: string, completed: boolean, priority: "low"|"medium"|"high" }
```

Распределение ответственности:
- `data.js` — исходные массивы `demoTasks` и `variantTasks`, номер варианта. Не содержит логики.
- `task-service.js` — 9 прикладных функций: валидация, создание, чтение, изменение без мутации.
- `task-extra.js` — расширение (поиск по подстроке).
- `main.js` — демонстрационный сценарий, импорт, вывод.
- `checks.js` — готовые проверки контрактов.

## Общий сценарий

| Этап | Всего | Выполнено | Осталось | Прогресс |
|------|-------|-----------|----------|----------|
| Исходный набор | 4 | 2 | 2 | 50.0% |
| После добавления id=20 | 5 | 2 | 3 | 40.0% |
| После выполнения id=4 | 5 | 3 | 2 | 60.0% |
| После переименования id=10 | 5 | 3 | 2 | 60.0% |
| После удаления id=7 | 4 | 3 | 1 | 75.0% |

Итоговые ID: `[1, 4, 10, 20]`. Единственная невыполненная — id=20.

Отказы продемонстрированы:
- повторное добавление id=20 → отказ без изменения состояния;
- передача строки `"true"` вместо boolean в `setTaskCompleted` → отказ.

Исходный `demoTasks` сохранил 4 записи с ID `[1, 4, 7, 10]`.
