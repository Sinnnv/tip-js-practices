## Организация кода

| Файл | Ответственность |
|---|---|
| `data.js` | Экспорт `demoTasks`, `variantTasks` и `variantNumber`. Никакой логики и DOM. |
| `task-service.js` | Девять прикладных функций из ПР2 (создание, чтение, изменение, удаление). Работает только с данными, не содержит обращений к `document`. |
| `task-selectors.js` | Функция `getVisibleTasks` — отбор задач по фильтру (`all`, `pending`, `completed`). Не изменяет входные данные. |
| `task-view.js` | Создание карточек (`createTaskElement`), отрисовка списка (`renderTaskList`), сводки (`renderSummary`) и пустого состояния (`renderEmptyState`). Только DOM, без изменения данных и подписок на события. |
| `main.js` | Состояние приложения (`currentTasks`, `currentFilter`), обработчики событий (`handleTaskListClick`, `handleFilterClick`), вызов `renderApp`. |

Полный список хранится в переменной `currentTasks` в `main.js`. Фильтр хранится в `currentFilter`. События обрабатываются в `main.js` через делегирование на контейнерах. Сводка вычисляется в `task-view.js` через вызов `getTaskStats` из `task-service.js`. Обработчики назначаются контейнерам один раз, вне `renderApp`.

## Отладка и клавиатура

Точка останова установлена на строке `const id = Number(card.dataset.taskId)` в функции `handleTaskListClick` файла `src/main.js`.

**Наблюдения при остановке:**
- `event.target` при клике на подпись кнопки — элемент `span.action-label`, а не сама кнопка.
- `event.target.closest("button[data-action]")` корректно находит родительскую кнопку.
- `card.dataset.taskId` до преобразования — строка `"4"`, тип `string`.
- После `Number()` — число `4`, проходит проверку `Number.isSafeInteger(id) && id > 0`.
- `findTaskById(currentTasks, 4)` возвращает объект задачи `{ id: 4, title: "Подготовить модель задач", completed: false, priority: "high" }`.
- После `setTaskCompleted(currentTasks, 4, true)` результат `{ ok: true, tasks: [...] }` присваивается в `currentTasks`, вызывается `renderApp`.
- После перерисовки фокус возвращается на кнопку toggle через `restoreTaskFocus(4, "toggle")`.

**Проверка отказа:**
- Через панель Elements изменён `data-task-id` карточки на `777`. После клика выведено сообщение «Задача с id=777 не найдена», данные не изменились.
- При значении `4abc` — `Number("4abc")` вернул `NaN`, `Number.isSafeInteger(NaN)` вернул `false`, действие проигнорировано без ошибки.
- Корректный выбор фильтра пересоздаёт карточки из настоящего массива и очищает сообщение об ошибке.

**Клавиатура:**
- Tab перемещает фокус между кнопками фильтров и действиями карточек.
- Enter и Space активируют кнопку (клик эмулируется браузером для `<button>`).
- После изменения статуса фокус возвращается на ту же кнопку toggle.
- После удаления карточки фокус переходит на активную кнопку фильтра.

## Вывод

Реализован браузерный интерфейс приложения управления задачами на основе модуля из ПР2. Данные и прикладная логика разделены: `task-service.js` не содержит обращений к DOM, а `task-view.js` и `main.js` не дублируют бизнес-логику.

Ключевые решения:
- Карточки создаются через DOM-методы (`createElement`, `append`), названия выводятся через `textContent` — это исключает интерпретацию HTML.
- Обработчики событий назначены контейнерам один раз (вне `renderApp`), используется делегирование через `closest`.
- Полный массив `currentTasks` хранится отдельно от фильтра, фильтрация не удаляет данные.
- Отказ операции не повреждает состояние: `result.tasks` присваивается только при `result.ok === true`.

Исправленная ошибка: в первой версии `task-view.js` использовался `await import()` внутри синхронной функции `renderApp`, что вызывало синтаксическую ошибку. Исправлено заменой на статический `import { getVisibleTasks }` в начале файла.

Различие между изменением данных и изменением DOM: изменение данных выполняется через функции ПР2 (`setTaskCompleted`, `removeTask`), которые возвращают новый массив. Изменение DOM выполняется через `renderApp`, который перерисовывает карточки из нового массива. Простое удаление `<li>` через DOM не является удалением задачи: после повторной отрисовки запись появилась бы снова, если массив не изменён.

Все 35 сервисных и 36 браузерных проверок пройдены. Общий и индивидуальный сценарии выполнены, фактические результаты совпали с ожидаемыми.
